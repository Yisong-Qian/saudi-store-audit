# 离线行为验收

本目录相关样例全部是合成数据，不含真实商品、表格链接或用户凭据。

- 输入：[marking-cases.json](../tests/fixtures/marking-cases.json)。
- 预期：[expected-marking-decisions.json](../tests/fixtures/expected-marking-decisions.json)。

19个场景覆盖在售、无划线价、残留数字价下的缺货OOS、Noon EOL优先级、同日清理、人工备注保护、EOL但在售、Status未知、Amazon自营及第三方发货/卖家、无默认报价、含运费选价、地区错误、页面失败以及同日恢复。

输入文件的common是每个案例的默认前提，案例同名字段覆盖默认值。案例相互独立；所有价格、卖家和库存均为给定的离线证据。空值表示空白，不表示本次允许清空旧值。

## 独立检查方式

将当前技能与输入文件交给一个独立评估会话，提供以下请求。不要先提供预期结果：

```text
只根据当前saudi-store-audit技能及标注样例做离线决策。不要访问网页、连接表格或改动真实数据。
逐案输出最终目标值、精确单格set/clear/unchanged操作、证据、统计分类，以及历史和基础列是否允许变更。
若遇到人工内容或未知字段，明确保留哪些内容及报告哪些冲突。检查规则优先级是否存在矛盾。
```

得到结果后再与预期文件逐案比较，重点核对：

1. OOS只生成在售价字段，Note只生成实际非平台卖家的sold by名称。
2. Noon指定不可用提示与EOL同时成立才适用三项留空；EOL但在售仍正常填价。
3. 清理只限当天已确认由巡店写入的内容；人工备注保留并报告冲突。
4. Amazon地区必须是Riyadh，未知卖家不能仅凭Amazon配送推定为自营。
5. 有购买选项不直接判缺货，按含运费总价选报价但售价记录商品价。
6. 失败行不误填OOS或0、不复制历史、不把部分核验计作整行完成。

项目的常规CI只检查包结构、工具行为及场景ID对应关系，不会调用模型，也不执行上述行为验收。离线样例通过不能替代真实页面核查及分批写后读回复核。

## 显示与缺链接验收

- Noon和Amazon的新建/复用日期组：数字售价和文本OOS正文均右对齐，OOS仍是文本，表头和日期居中。
- 缺链接行新Note为空；当天旧自动失败说明或自动卖家Note有归属证据时清空，价格/Buy Box仅保留为未核实；人工Note或公式保留并报告冲突。此规则不要求商品页证据。
- 其他访问失败仍保留当天未知旧值，不将未知改成OOS/0。
- 英文、阿拉伯文和最长卖家Note按完整内容自动列宽、单行显示，字符串、字号、行高和历史列不变；全空Note列不缩窄。
- 同日重复执行不新增日期组，已空Note无须重复清空；结束时读回对齐与值，并实际查看两张Google Sheets。

这些格式与缺链接场景须结合实际单元格元数据及Google渲染检查；包校验或现有合成价格样例不等于通过显示验收。
