# 每日新增日期列组

本规则实现横向逐日记录，不覆盖历史。每次运行固定选定时区（默认Asia/Shanghai）的实际开始日期D，显示yyyy/m/d；不存在当天组才新建。同一天重试或重跑不重复建列。

## 定位

1. 读实时工作表元数据与有界表头区，扫描已有使用列；不要只扫描最初26列。必要时按列块继续扫描。
2. 按“字段顺序+相邻日期单元格/合并日期范围”识别完整列组，不能仅搜索某个Note或MSRP标题。
3. 日期支持实际DATE序列值（Sheets基准1899-12-30）及yyyy/m/d、yyyy-mm-dd文本；以日历日期比较，不把时区转换变成前一天。
4. Noon模板：字段行1，日期行2，产品从第3行；每组MSRP、Price、Note共3列。Amazon模板：日期行1，字段行2，产品从第3行；每组MSRP(SAR)、Offer Price、buy box、Note共4列。实时用户调整的布局优先，无法唯一识别就报告。
5. 当D已有唯一完整组时复用该组；不修改其日期或历史组。有两个D组、D组不完整、表头与日期对应关系不清时，不能擅选或再建第三组，停止该表结构写入并报告。
6. D不存在时，在全部已使用列的右侧追加完整新组。若已有空白列容得下就使用；网格不足时仅appendDimension扩展右端列数。不可覆盖右侧人工汇总/备注、插入已有历史组中间，或删除旧列来腾空间。

## 创建

写前再次读表头和目标空白区域，防止另一轮刚创建相同日期或用户填入内容。保存源样板与所有既有列的值、链接、公式、格式及需要的结构基线。

一个原子结构批次应尽量完成：
- 如需，appendDimension增加确切缺少列数；
- 对新组用copyPaste的PASTE_FORMAT从最近同类完整组复制样式，只覆盖本次新列及必要使用行；
- 适用且已确认的验证规则可单独复制，不能复制数据/公式/链接/昨天Note；
- 写新组字段名与日期；新日期行只在该组宽度内mergeCells为一行并居中，保留源表的日期/字段行次序；
- 在可读取列宽时让新列匹配对应样板列宽；不得改变旧列宽。价格数据应支持数字/货币及缺货文本OOS，buy box为整数，Note为卖家文本，不能把日期格式误用于价格数据；验证限制若不允许OOS则报告冲突，不强改旧规则。

不使用PASTE_NORMAL、PASTE_VALUES或整组复制再清空的方式。新组产品数据从空白开始，旧组只做样式来源，历史报价和库存状态不带入。

日期可用本地日历计算为Sheets序列值并对日期范围应用DATE格式yyyy/m/d；日期的numberFormat、水平居中及合并只应用在新日期行。数字/文字字段值用updateCells；格式请求严格限定新组范围。

若存在同日组，只做读回及必要当天价格刷新，不重复复制格式、再次合并或改历史日期。新组已创建但进程中断，恢复时先识别该组再继续，不能无条件新增。

## 例子（仅结构示意）

- Noon已存在F:H=2026/10/19、I:K=2026/10/20；实际运行2026/10/21且右侧空白，则新建L:N；字段L1:N1=MSRP/Price/Note，日期L2:N2合并=2026/10/21，数据从第3行。
- 同一布局实际运行2026/10/20：复用I:K，F:H历史不可修改。
- Amazon已有G:J=2026/10/20，实际运行2026/10/21且右侧空白，则新建K:N；日期K1:N1合并=2026/10/21，字段K2:N2=MSRP(SAR)/Offer Price/buy box/Note。
- 如果Amazon的K列已有人工汇总，则新组追加到全部已用列之后；不能拿K:N直接覆盖。
- 列数不足时在右端增加缺少列；不能新增整张工作表替代原表，也不能搬移基础产品列。

## 验收

1. 读回新增/复用组：D只出现一组、字段齐全顺序正确、日期合并范围仅本组3/4列、下方数据未混入旧值。
2. 对比所有原有列的值、日期标签、链接、公式和格式未变。新增组的字体、底色、边框及字段/日期位置匹配同平台样板。
3. 价格字段回写后在Google Sheets实际界面检查本日组与相邻历史组，特别排查数字显示成日期、OOS文本不正确、重复日期组和跨组合并；Note仅含已核实的非平台卖家，Noon EOL例外按writeback.md检查当天三项留空。
4. 报告两表本次新建或复用的明确A1范围与日期。表结构准备成功不等于网页查价或数据写入成功；分开报告。
5. 中断或审批拒绝时先读回实际状态；不盲目重放插列/合并请求。已建当天组保留，后续恢复从该组继续。
6. 跨日遗漏不补造历史实时价。按实际运行日创建/复用组，并记录与预期计划的时间偏差。
