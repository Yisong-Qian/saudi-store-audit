# 沙特电商巡店

每次调用执行一次新的巡店；按本次实际运行日期在原表创建或复用当天的列组。所有价格、库存和卖家来自本次商品网页，历史日期组只读保留。

## 表格配置

用户本次明确提供的表格URL和范围优先；否则读取本技能内可选的 `references/store-config.local.json`。文件不存在时，可参考 [references/store-config.example.json](references/store-config.example.json) 创建自己的本地配置；示例不含真实表格链接。没有已授权的目标URL就先向用户询问，不能猜默认表格或读取别人的表。

配置包含 `spreadsheet_url`、两表名称、日期时区、建议运行时刻及Amazon配送地区。配置中的工作表名称只是定位线索；开始前读取实时元数据确定实际名称和sheetId，不套用某个用户的sheetId。本地配置不随GitHub项目、安装包或ZIP分发。

| 工作表默认名称 | 商品链接 | 每天新增的列组 |
|---|---|---|
| Noon | LINK表头对应的实际商品URL | MSRP / Price / Note，每天3列 |
| Amazon | 实际商品URL或Go!超链接 | MSRP(SAR) / Offer Price / buy box / Note，每天4列 |

先读实时元数据、日期和字段表头、行身份；不能套用旧列号、行号或产品数。产品范围不固定：每次运行都以实时表格为准，产品行从第 3 行到 A 列最后一行有产品的行（Noon 为 Customer Model、Amazon 为 ASIN），表里有多少行产品就按链接逐行查多少行；不沿用旧记录的产品数或行号；表里新增或删除产品时自动跟随。Noon的Status按表头定位，不固定读取某个列号。Amazon某些模板的基础Note列实际是商品链接；不能将它当作当天价格组中的Note覆盖。识别不清时暂停受影响范围写入，不能猜。

## 每日日期列组

开始布局或写入前读 [references/daily-columns.md](references/daily-columns.md)。日期默认以Asia/Shanghai为准，用户本次明确指定或本地配置提供其他日期时区时采用该时区；格式yyyy/m/d，同次运行固定同一天。

- Noon沿用“第1行字段名，第2行日期”的布局；日期横跨该组3列合并居中。Amazon沿用“第1行日期，第2行字段名”的布局，日期横跨该组4列合并居中；若用户后来明确调整布局，按实时模板识别，不强制重排旧组。
- 当天组不存在：在右侧安全的空白列新建，按最近同类完整组复制样式——只复制第 1–2 行（表头与日期行）的格式，数据行（第 3 行起）一律不复制：上一组的黄色高亮、红色字体、单元格备注都在数据行上，不复制数据行就带不过来；数据行写值前按默认格式显式设置（底色白色、字体默认色、无备注、价格列 NUMBER、售价右对齐、Note 从左到右/左对齐/单行），并读回确认无任何黄色、红色字体与备注，再开始回写。只复制格式、适用的验证及表头结构，不能复制昨天的价格、库存、Buy Box、Note、公式或整组内容。
- 当天已有唯一完整组：复用，不重复建列；同日重跑或失败重试也只操作当天组。当日有多个同名组、日期无效或字段不全时，先核对结构，未能唯一定位则停止该表写入并报告。
- 只编辑本次日期组。历史组、日期标签、产品基础信息、链接及人工信息均保留，不清理、改日期或覆盖昨天的数据。无法核实的当天新单元格留空，失败行及原因写入巡店报告，不写入Note；不从历史组带入值。
- 可读、可写且有足够空列时才创建组；需要增加网格列数时仅在表右端扩容。新组可按模板创建格式；新建和复用当天组均须按回写规则统一售价正文右对齐，并统一当天Note正文从左到右、左对齐，适配其单行显示与列宽。除此之外不整表重排，不改历史组格式。

用户调用本Skill完成巡店并更新原表时，在已授权的表及字段内执行；仅创建或阅读Skill不运行巡店。没有明确要求定时执行时，不创建自动化或新聊天。

## 读取和准备

1. 使用已连接的Google Drive / Google Sheets工具读写原表；有对应技能时遵循其现有表格编辑流程。不要为交付新建、复制、导入或替换整本表格。
2. 使用可交互浏览器检查网页与Amazon地区，优先复用可访问的会话。缺少工具或权限时先完成可做的工作，准确报告阻塞，不声称已连接。
3. 有界读取所有产品行并检查表尾：先读 A 列确定最后一行产品（最后一行非空产品标识），产品行为第 3 行至该行，中间空行不截断后续行；没有链接的行当天留空，但仍计入产品行。识别hyperlink、富文本链接、HYPERLINK公式及纯URL；Go!/GO!文字不等于有链接。不能从型号、ASIN或NIN自动拼替代网址后当作原表链接。
4. 保存本次行身份（sheetId、行号、型号/编号、原始链接、Noon的Status值及其表头位置）、目标字段原值/公式/验证约束及必要格式基线。空行、表头、日期行不计为产品。回写前重读Status，避免状态变化后误写EOL行。
5. 日期按本次选定的时区记录；保存历史组和基础列的原值、公式、链接与样式基线。保留原表头、Status、颜色、字体、行高和人工备注；仅允许当天售价正文的右对齐、当天Note从左到右、左对齐、单行显示及列宽适配，其他既有格式和列宽保持不变。

## 逐行网页核验

- 每个有链接的产品都打开原表该行的超链接，保留网址中的变体、套装及卖家参数。以该链接实际打开的沙特商品页及主报价为准，直接记录该页价格。型号、商品编号（NIN/ASIN）、标题或规格之间的差异不作为跳过查价的理由。若链接无法打开或没有进入商品页，记录网页核验问题；Noon 的临时拒绝访问按下方重试规则处理。
- 取主商品当前选中报价；不以推荐商品、其他变体、分期、每件折算价、购物车合计或“其他卖家最低价”替代主报价。截图示例只说明字段含义。
- 在售时Price / Offer Price填页面公开显示的当前商品价，币种SAR；确认缺货时填文本 `OOS`，不填仍残留的数字售价。优惠码、信用卡优惠、返现、会员条件不额外扣除；运费、成色等详细信息保存在巡店记录，不写进Note。
- MSRP只填该报价对应的可见划线原价，包括List Price、Was、Bundle List Price。不能取普通未划线数字、其他规格或推荐商品原价。
- 只有导航、空正文、骨架或未加载完的购买面板时，等待加载后再查；首次没找到价格节点不等于缺货。普通加载异常通常至多重载或重开两次，仍不能核实则记录原因；Noon 临时拒绝访问按下方规则重试。
- 每行留存时间、商品页实际URL、各价格的显示/缺失/未知状态、库存、卖家/发货方及证据摘要。复杂报价可截图，详细证据写入巡店记录，不塞进Note。
- 每字段分别判定“已查得数值/OOS”“确认不显示”“未知”，另记录Noon的EOL留空例外。证据没提到某字段不等于确认没有；未知字段只可保留当天已有值并在报告说明本次未核实，不能从历史组取值，也不能因为售价已查到就把整行记为完成。

### Noon

- **临时拒绝访问重试**：Noon 商品链接首次出现 `Access Denied`、拒绝访问或同类临时访问拦截时，先加入本日待重试队列，记录行号、原表链接、尝试时间与页面提示。先完成其他商品，再在同一正常浏览器会话中逐个重开原表链接，仍被拒绝时按页面提示等待或逐步延长间隔，继续分轮重试，不受普通页面加载的两次重试限制。以同日商品页核实到当前售价、明确缺货或确认 EOL 留空为该行的完成条件。核实后回写当日已有日期组并读回；只按页面证据给值。遇到需要人工处理的验证码、登录或明确权限阻塞，或运行时限结束，保留待重试行和原因；当日能恢复运行时优先接续。按选定时区跨日后，重新采集新一天的报价。报告分别列出重试恢复和仍待核实的行；仍待核实不能标为OOS。
- 优先检查EOL例外：页面显示 `This product is not available` 且同一行Status去除首尾空白后为 `EOL`，当天MSRP、Price、Note均留空，不写OOS或卖家。新组不填；同日重跑仅精确清理本日由巡店自动写入的三个字段，历史和人工内容保留，冲突写入报告。该行单列为EOL跳过，不归为核验失败。
- 上述页面不可用但Status不能可靠读取/定位时，暂停该行目标写入并在报告说明，不猜测为非EOL。
- 其他在售行：MSRP填可见划线价，无则留空；Price填当前商品价。
- 明确显示 `This product is not available`、Out of stock或明确等价缺货提示，且不属于上述EOL例外时，Price填文本 `OOS`；MSRP仍仅填可核实的可见划线价，无则留空。页面加载失败、缺链接不能当作缺货。
- 卖家为noon时Note留空；实际非noon卖家已核实时，只写 `sold by 实际卖家名`。noon Express不等于卖家为noon。缺货时也仅在实际非平台卖家可核实时填写卖家，不在Note写缺货状态。

### Amazon.sa

- **先确认配送地区为Riyadh, Saudi Arabia。** 已显示Riyadh且站点为Amazon.sa即可复用设置；逐页确认地区未丢失。不能将其他地区报价写成Riyadh结果。
- **以用户登录后的默认视图为准，取默认选中的购买方式的价格**：云端浏览器（Environment 1，默认 profile）已登录用户的 Amazon 账号，页面打开时默认选中的购买方式与用户 Chrome 一致。核查 Amazon 页面时先确认已登录（页眉显示“Hello, Qian”）：已登录时，直接读取页面打开时默认选中的购买方式的价格，不固定优先一次性购买（One-time purchase，Amazon.sa）；如果默认选中的是 Amazon Now，即使页面有一性购买选项，也取 Amazon Now 的价格。所选购买方式的选项必须在页面上实际看到才记录；看不到就不得记录该价格。两种方式的价格与 List Price 可能不同，记录所选方式对应的价格。若发现未登录（页眉显示“Hello, sign in”或要求登录）：不要取匿名浏览器的默认档（匿名默认是 Amazon Now，与用户看到的不一致），也不要按本地配置 `references/store-config.local.json` 里的 `default_purchase_option` 取值——停止 Amazon 部分的核查，并在报告里注明登录已过期、请用户重新登录，等她重新登录后再补跑当天的 Amazon 部分（本地配置只记录已核实的默认购买方式作参考，不作登录失效时的取值依据）。Noon 不需要登录，正常进行。不要在巡店中自行重新登录（登录验证码发到用户手机 WhatsApp，需她本人提供）。
- **规格匹配**：页面有多个规格/尺寸/款式选项时，记价前必须确认当前选中的规格名与 List Price 与表里该行一致（规格名、List Price 都对上）；页面默认选中其他规格时，切换到正确规格再读价；绝不从规格选项列表里取其他规格的价格。套装（Kit/Bundle/2Pack）须确认选中款式确为表里该套装，单只装与多件装不得混淆。
- **buy box 判定**：按所记录的那档报价（用户 Chrome 默认选中的那档）的 Shipper / Seller 判定——发货方与卖家同时为 Amazon.sa 时 buy box=1，否则 buy box=0（包括 Amazon Now、Amazon UAE / Amazon.ae / Amazon Resale、第三方卖家）。Delivered/Fulfilled by Amazon.sa 不足以判 1；Amazon UAE、Amazon.ae、Amazon Resale 不能自动等同 Amazon.sa。页面展示价格时 buy box 填 1 或 0；确实无法判定卖家/发货方时留空并记报告。
- **Note 卖家写法**：卖家为 Amazon.sa 时 Note 留空；卖家为 Amazon Now 时 Note 写 `sold by Amazon Now`；实际非平台卖家（包括 Amazon UAE）已核实时，Note 只写 `sold by 实际卖家名`。卖家未知不能猜名称。页面显示剩余库存标识时追加 `N left`（见“每日刷新与卖家Note”一节），两者都满足时合并为 `sold by <实际卖家名>; N left`。
- 页面明确显示 `currently unavailable` 或明确等价缺货提示，且没有当前可售报价时，Offer Price填文本 `OOS`，buy box=0。MSRP仍仅填可核实的可见划线价，无则留空；Note只记录已核实的实际非平台卖家，不写缺货状态。
- **除缺货外，页面主购买框没有展示价格时，整行留空**：页面只显示“No featured offers available”或类似提示、主购买框无价格时，不打开 See All Buying Options 找价，不记录购买选项里的第三方报价；当天 MSRP、Offer Price、buy box、Note 四项全部留空。页面显示“from SAR X”（如“2 options from SAR185.00”）时，X 就是展示的价格，按默认报价处理，不按此留空。
- 价格可核实但卖家或发货方未显示：先展开相关购买信息或重试；仍无法核实时可填当天已确认价格；buy box 仍按证据填 0（非 Amazon.sa 主体已确认时）或留空（无法判断时），并在报告明确本次未核实。Note不写核验失败说明，不复制昨天的buy box或卖家。

## 每日刷新与卖家Note

开始回写前读 [references/writeback.md](references/writeback.md)，区分确认缺失、未知及备注归属。

- **确认缺失**：完整商品页确认无划线价，则当天MSRP留空；只有同日重跑且当天格属于巡店写入时，才可精确清空该旧格。确认缺货的售价应写 `OOS`，不能因没有数字售价而清空或保留残留数字；Noon的EOL例外优先。历史价格不变。
- **缺少商品链接**：当天新价格/Buy Box/Note留空，不写核验失败说明。当天已有且可证明由巡店生成的Note须精确清空，包括旧失败说明和旧自动卖家Note；先记录原值、归属及缺链接证据，不要求取得无法打开的商品页。人工备注、公式或归属不明内容保留并报告冲突。已有价格/Buy Box保留为本次未核实，失败行和原因只进入报告，不猜价、不标OOS。
- **其他无法查证**：访问失败、未打开商品页或未完成加载时，新目标格留空；同日旧值保留并在报告说明本次未核实，不把未知当作缺失。上述缺链接Note清理规则优先于一般失败保留规则；历史格不改。
- 本次自动生成的Note只能是 `sold by <卖家名>`、`N left`、两者组合 `sold by <卖家名>; N left`，或空白；其中卖家名指已核实的非平台卖家或 Amazon Now，Amazon.sa 不写进 Note；不写缺货、OOS、核验失败、日期、正常自营说明、发货方、运费或成色。页面显示剩余库存标识（如 Amazon 的 Only N left in stock）时，Note 写 `N left`，数字以页面为准（如仅剩 1 件写 `1 left`）；同时有已核实卖家（非平台卖家或 Amazon Now）时写 `sold by <卖家名>; N left`。卖家未知不能猜名称，相关证据和问题另存报告。
- **异常标注分三档**：①当天价格有变动（与昨日相比，两日均为数字售价且数值不同）：不写备注、不标黄，只把当天 Price（Noon）/ Offer Price（Amazon）格的数字标红（字体颜色 RGB 1,0,0）；只标售价格，MSRP 格不标红；缺货/OOS 状态变化不标红。②卖家变化、buy box 变化：不写备注、不标黄；Note 格按正常规则写当前卖家（如 `sold by <实际卖家>`），buy box 格写当前值，变化通过与昨日组对比可见。③页面加载失败、被拦截、未核实、需人工审核：这是唯一标黄加备注的情形，当天 Note 格背景填黄色（RGB 1,1,0），并在该格单元格备注写明原因，如「页面被拦截，未核实」「页面加载失败，未核实」。已确认缺货只在 Price/Offer 格写 `OOS`，不写备注、不标黄；EOL 行整行留空、不标注。Noon 没有卖家/buy box 概念，只适用价格变动与打不开两项。黄色与红色只出现在当天组，不改历史组。
- **列宽合适**：写完所有数据后，把当天 Note 列宽调到刚好完整显示格子里最长一条文本（只按格子里的文字算，单元格备注里的文字不占列宽；也不要设得过宽）。先执行自动列宽，再按最长文本核对：按字符估算所需宽度——中文每字约 13px、英文/数字每字约 7px、阿拉伯文每字约 8px，另加 10px 边距；自动列宽给出的值若小于估算值，以估算值为准（自动列宽会低估中文宽度）；不够加宽、太宽收窄，最后读回列宽核实。只做自动列宽不可靠，必须再核对一次。列宽以列里当前最长一条文本为准，用户在巡店后又往 Note 列里加了更长的文字时，也按同样方法把列宽加宽到能完整显示。Amazon 的 MSRP / Offer Price / buy box 三列列宽固定：MSRP 136px、Offer Price 132px、buy box 132px（以 2026/11/22 组为准）；新建日期组时按此固定值设置，不随内容自动调整；复用组若宽度被改动，恢复为此固定值。
- 同日状态恢复时，把当天Price / Offer Price中的OOS替换为已核实数字售价；仅在卖家已核实后更新当天卖家Note。历史组保持不变。当天旧缺货长备注、旧巡店失败说明等，只有归属可确定为巡店写入时才可按本次证据清理，不迁移到历史。
- 所有当天清理都须确认原值属于巡店自动写入；明确巡店前缀或与本日前次写入记录匹配可作为依据。无法确定归属的人工值、Note、公式不整格覆盖或自动删减；保留并在报告列出冲突，包括EOL例外未能完全留空的格。
- **显示要求**：数字售价与文本OOS在当天Price / Offer Price正文统一水平右对齐，日期和字段表头仍按原样居中。每批写后检查对齐；当天Note正文统一textDirection=LEFT_TO_RIGHT、horizontalAlignment=LEFT，有卖家时视觉顺序固定为sold by在左、店铺原名在后，只有 `N left` 时只写该文本；阿语店名内部保持正常阿语阅读顺序，不翻译、不倒序、不插入隐藏方向控制字符，不改变整张工作表方向。每轮结束对有内容的当天Note按完整文字自动列宽，单行显示，不缩小字体、不增加行高、不改卖家名称原文；全空Note列保留现有或模板宽度。精确格式操作见writeback.md。
- 更新本Skill本身不回头改表格或历史报告；只有用户明确要求修正现有日期组时才执行相应修正。

## 分批回写与复核

1. 日期组建立或定位并读回复核后，通常5–15个产品一批回写。写前重读日期、字段、目标行、链接、Noon的Status及目标原值；发生插列、插行、换链接或并发编辑时重新映射受影响范围。
2. 为具体单元格列出旧值、新值、本次证据。数据写入只写已核实字段的userEnteredValue，数字价格用numberValue、OOS用stringValue；另以精确格式请求统一当天售价正文右对齐及当天Note从左到右、左对齐和单行显示，轮次结束仅对有内容的当天Note列自动列宽。不整行重写，不把未知转换成0、OOS或空白。
3. 清空仅限当天组已确认缺失、EOL例外、缺链接行的自动Note或同日过期巡店Note，须有归属证据、原值记录和明确单格范围；不能用跨列空对象清空其他字段或历史组。人工内容、公式/验证与直接写值冲突时保留并报告。
4. 每批写后读回，逐格比较数值、文本OOS、空白、Buy Box、完整卖家Note。传输结果不明时先读回，再补写尚未生效的具体单元格。复核结论以实际读回的单元格值为准，不能用计划写入的值代替；读回发现不一致时纠正该格并在报告中说明。
5. 自动审批拒绝时处理不受影响项；只有缩小范围或新证据解决具体原因后才重试，不换接口绕过。仍受阻则报告具体单元格及原因。
6. 运行中允许“待加载”“待确认地区”“部分字段已核实”状态，并继续处理这些待办。只有原链接打开的商品页、所需地区、价格显示状态、库存及适用卖家/Buy Box字段均已核实，才计作整行页面核验完成（明确缺货时卖家/划线价的确认缺失也是有效结果）。Noon的EOL例外不要求补查不再填写的价格和卖家，单独计为EOL跳过。结束时分列完成页面核验、EOL跳过、缺少链接、部分核验/网页失败、人工/公式冲突、写入/复核失败。部分字段成功不混入整行完成数；页面核验与回写分别统计，缺货不是访问失败，尝试写入不是已完成。
7. 最终对比所有历史组和基础列原值、链接、公式、验证及格式；仅允许新组所需的新增列/合并/格式，以及当天售价正文右对齐、当天Note从左到右、左对齐、单行显示和列宽适配。在实际Google Sheets检查两表当天组和相邻历史组，确认OOS右对齐、缺链接自动Note为空、最长英文和阿拉伯文Note均由左侧sold by开始，店名完整单行显示；不整表重排。
8. 简短汇报原表链接、本次日期、两表新建或复用的具体列范围、产品数/页面核验数/EOL跳过数/回写并复核成功数、各字段更新单元格数、OOS缺货数、非平台卖家、失败行及原因。EOL跳过不混入普通OOS或失败行，若清理当天旧值则另报已清理格数。无异常且结果与当日已完成记录无变化的重复触发可保持安静；日常首次完成、状态变化、失败或需用户处理时报告。汇报在常规结果后单列「异常」一段，见巡后复查与异常报告。详细证据另存，不把历史值当作当天结果。

## 巡后复查与异常报告

回写结束后、汇报之前，读回当天两表的新日期组逐项复查：当天组是否存在、列范围与日期是否正确，有无误建或多扩的列；回写数是否与核验数对得上，有无复核差异、漏写或多写；与昨日组逐行比对，列出所有变化（价格变、OOS 变、卖家变、buy box 变）。复查结论以实际读回的单元格值为准，不能用计划写入的值代替；发现不一致时纠正该格并在报告中说明。

汇报在常规结果后单列「异常」一段，包含：页面加载失败或未核实的行、新确认缺货的行、卖家或 buy box 变化、单日价格变动超过 20% 的行、回写复核差异、建组或格式错误及已纠正的处理。无异常时写「本次无异常」。只报实际查到或读回确认的，不猜测。复查时也核对当天的黄色与红色：黄色只出现在当天需人工审核的行上，红色只出现在当天价格有变动的行上；上一组残留的高亮与红色字体要清除（只清当天组，不动历史组）。回写结束、复核完成后，清除当天组内产品末行之下的残留底色：把当天组在最后一行产品之下的单元格背景恢复为白色，不留表头色的填充；只清当天组，不动历史组；清除后读回复核。

## 每日自动巡店

推荐示例为周一至周五北京时间10:00（Asia/Shanghai，沙特05:00），目标为用户已配置的两个工作表；以用户实际选择的星期、时间及时区为准。按此示例调度时，运行前检查Asia/Shanghai的星期；周六、周日直接跳过，不开商品页、不建组、不回写，也不补抓周末价格。安装本技能不会创建、迁移或启用任何定时任务。仅在用户明确要求设置或修改定时任务时，用应用的自动化功能建立或维护本聊天的每日任务，提示中显式调用本Skill、写明表格URL和日期列组规则；不创建重复任务。定时触发时只执行巡店，不再次创建/更新定时器。Skill文件更新本身不会新建定时器。

每次定时执行都以实际运行日期建组、现场逐行查验并回写。若漏跑，不把恢复时查到的价格伪填成过去日期；只记录实际运行日，报告漏跑。上一轮仍执行时避免并发建组。浏览器、连接、权限或审批阻塞时记录实际进度并报告，不能伪称已自动完成。涉及本地Skill和浏览器的任务需要运行电脑及应用保持可用。
